# İleri aşamalar yol haritası (6-ajan derin tasarım workflow)

## North Star
A camera-agnostic, calibrate-once analytics layer that turns any fixed night halısaha camera into an honest, watchable 2D match replay plus defensible per-player and collective insights, pooling thousands of real amateur players per venue. It refuses, never fabricates, what a single night camera cannot see (ball height, individual appearance ID, fake 7-7 team splits, survey-grade metres).

## Fazlar
### Faz 1: Stable within-match identity (backbone fusion)
- Lock the pipeline order that already exists: track_robust.presplit -> track_stitch.stitch -> track_robust.bridge_gaps -> player_state, so every downstream stage consumes the swap-repaired, gap-bridged player_id (Step 0 plumbing of done modules).
- New detect/player_id.py: thin fusion layer emitting one identity card per player_id (role core/partial, presence timeline, home-zone/occupancy ellipse from player_state, kit_signature from team_split, team_id+conf, seam_swap_risk, id_stability_score). No new model.
- id_stability_score = f(timeline_coverage, n_seam_swaps, observed-vs-predicted fraction); low-stability ids surfaced as low_confidence, not hidden (mirrors residual_under_merge honesty).
- Team-layer REFUSE / one-sided-vest hardening: on degenerate-colour or mixed-kit, emit team_id=-1 for the bad side, confidently label only the uniform-vest team, roster~7 soft prior, never force a balance.
- tests/test_player_id.py + a ~14-id hand-labelled GT set on cankaya_cam2 to MEASURE within-match id-purity/fragmentation (measurement only, not needed to run).

**Açar:** One stable, anonymous, over-merge-proof player_id plus an identity card that EVERY downstream stage (replay, analytics, continuity, cross-match) keys on, and an honest team layer that refuses a fabricated 7-7. CPU-only, no GPU, no labeling on the run path.

### Faz 2: Watchable 2D match replay (first shippable B2B artifact)
- stats/match2d.py:build_replay — one versioned 'replay' artifact (parquet + JSON sidecar) off continuous_state(), calib QA-gated fail-closed, team labels locked once per id, resampled to ~10-12 playback fps, carrying status/conf/unit/scale honesty metadata.
- Shared pitch-geometry helper (reuse homography._template_segments_m/_dims_m) so the MP4 and the web player draw the identical metre-space pitch.
- Secondary renderer: matplotlib Agg -> system-ffmpeg subprocess MP4 (LGPL tool invoked, not bundled) for sharing/DMs.
- Primary renderer: self-contained web/replay/player.html canvas player (play/pause/scrub/speed, team toggle, confidence-fade, on-screen honesty legend) — zero server compute, B2B iframe-embeddable like /oda.
- Honesty encoded as code-asserts and markers: observed=filled dot, interpolated=hollow ring, predicted=faint+fading trail; no row outside a player's active span; on-pitch counter vs roster ~14; tests/test_match2d.py.

**Açar:** The first thing a platform like sosyalhalisaha.com can actually SEE and embed — a watchable, honest top-down replay — delivered early on the existing single-venue calib with NO GPU/labeling. The replay artifact schema is the same file reused for every pooled match later.

### Faz 3: Position-derived match analytics (the watchable story)
- stats/match_eval.py time-series fed by continuous_state (NOT raw dets): collective shape (convex hull, spread, length, width, nearest-neighbour spacing) per frame, tagged with observed_frac and greyed below a floor.
- Tempo/intensity timeline (rolling conf-weighted observed-only speed) + per-player burst/load; relative percentiles unless scale is exact.
- Territory/occupancy timeline (def/mid/att thirds) + per-player Voronoi space-control share (scipy.spatial, cells half-plane-clipped to the pitch polygon).
- Team-conditioned metrics (per-team compactness, line separation, pressing PROXY) behind a hard team gate; emitted DEFERRED with balance_note when the gate fails.
- 'Review markers' (convergence + tempo spike in a goal-third) as candidate timestamps, explicitly NOT detected shots/goals/passes; possession_pct stays None; additive in_game block + 3 viz panels + tests/test_match_eval.py.

**Açar:** A defensible per-match insight layer on top of the replay (tempo, territory, compactness, space-control, load) that is valid WITHOUT a ball and WITHOUT reliable team ID. Completes the early, single-venue watchable product without touching the hard stages.

### Faz 4: Per-venue auto-calibration (generalization + pooling gate)
- pitch/venue_autocalib.py: fully camera-agnostic calibration (venues differ in aspect/focal/distortion/resolution) that calibrates a fixed camera ONCE from its own footage.
- Fail-closed QA reuse (accept_calib_qa) so a bad auto-calib rejects the run rather than producing perspective-biased confident-wrong output.
- Calibrate-once-per-venue, then pool MANY matches from that fixed camera -> thousands of distinct players; tightens metric-mode scale where an on-site anchor exists.
- Provides the metric motion gate, the homography-predicted ball-size prior, the physical max-speed gate, and metric projection that later stages depend on.

**Açar:** Generalization beyond cankaya_cam2 to ANY venue camera, and the per-venue match pooling that is the actual business (thousands of real amateur players). Started in parallel today; it is the gate for cross-match identity (Phase 5) and the ball size/speed priors (Phase 6).

### Faz 5: Full-match continuity at scale + cross-match identity
- Eval harness FIRST: hand-label persistent IDs on one 2-3 min night segment; IDF1/HOTA/ID-switch/fragmentation/MT-ML on raw ByteTrack vs current stitch (real, measured continuity numbers).
- Refactor stitch() body into a pure associate(); detect/track_continuity.py runs it over OVERLAPPING windows sized by tracklet count (kills the 60-min N^2 blowup), then a Level-2 cross-window stitch in the overlap zone.
- Roster-anchored constant-identity layer: pin K core slots to the K longest chains; model substitutions as explicit touchline hand-offs (substitution_events), never ID churn; preserve clique_floor and temporal_violations==0.
- Crossing-aware re-association (cross-team only, via colour veto + velocity continuity); same-team crossings flagged in audit_seams, NOT resolved; optional 4090 appearance probe that is expected to confirm the chance-level negative.
- Cross-match / per-venue gallery (depends on Phase 4): link a new-match id to a person ONLY on a legible jersey number or operator re-enrollment; colour/home-zone only RANK candidates for a human, never auto-assert; unmatched -> new anonymous venue id.

**Açar:** Production-grade identity on real 60-min full matches (the demo ran on a 12-min clip) and honest cross-match linking that scales the Phase 4 pool into named/persistent players where, and only where, external input exists.

### Faz 6: Ball layer + best-effort jersey OCR + named enrollment (hardest, deferred)
- Ball Stage 1 (no labels): RF-DETR ball class at low threshold (top-K) + far-band tiling, UNION with fixed-camera background-subtraction blobs gated by the homography ball-size prior; Viterbi/DP trajectory association with an explicit no-ball state; image-space Kalman; airborne segments flagged metric_status='airborne_unreliable'.
- Sparse ball GT via pick_points.py + eval/ball_eval.py: visible-recall, precision, coverage %, and a FABRICATION AUDIT (emitted positions during human-invisible spans must be ~0). Ship as labeled layer only if precision>=~90% and visible-recall clears the bar, else BETA/sparse or refuse.
- Ball Stage 2 ONLY if the Stage-1 ceiling is too low: license-vetted TrackNet/WASB-style heatmap net, 4090 rental + night labeling — gated strictly behind the measurement.
- detect/jersey_ocr.py (PaddleOCR/Tesseract Apache, CPU): precision-first, near/mid-third only, multi-frame agreement on the same player_id; far third reported 'not legible'.
- One-time manual enrollment helper (reuse topdown_viz crops, ~14 clicks/match) — the only honest route to NAMED identity; gates downstream possession/touch to observed ball spans only, with coverage % printed.

**Açar:** The genuinely hard, prerequisite-bound extras (ball-derived touch/possession, jersey numbers, named players). Deliberately last: each needs Phase 4 calibration priors and/or labeling, and each must fail-closed rather than fabricate the non-physical.

## Kritik yol
Detection/recall (done, ~73-82% precision~100%) -> a QA-gated metric homography motion gate (single-venue done; pitch/venue_autocalib.py for generalization) -> stable within-match player_id from presplit/stitch/bridge fused in detect/player_id.py. That stable id is the single chokepoint: replay, analytics, continuity, team, OCR and cross-match all key on it, so nothing downstream is meaningful until it is locked. For SCALE specifically the gating chain is venue_autocalib -> windowed full-match continuity -> per-venue cross-match pooling -> thousands of players. Ball and named-id sit OFF this path as optional fail-closed layers.

## Sıralama gerekçesi
Order is driven by two facts: (1) the identity backbone, calibration on the canonical venue, and continuous_state already exist, so the cheapest high-value move is to fuse them into a stable player_id and immediately render a watchable replay and analytics on the ONE existing calib — a demo-able B2B product with no GPU, no labeling, no auto-calib dependency. (2) The genuinely hard or prerequisite-bound work (camera-agnostic auto-calibration, 60-min windowed continuity with a labeled eval harness, cross-match linking, ball, fine team-id) is deferred until its inputs exist, so we never block the early product on it. Auto-calibration is foundational for SCALE (multi-venue + pooling + ball priors) but not for the single-venue watchable demo, so it runs as a parallel track that lands before cross-match and ball rather than before the first deliverable. Throughout, appearance is kept motion-secondary because we MEASURED it at chance at night (intra 0.59 ~ inter 0.58), and every team/ball/scale/name output is gated to REFUSE rather than fabricate.

## Hızlı kazanımlar
- Step 0 pipeline-order lock (presplit -> stitch -> bridge -> player_state) — near-zero cost, already-wired modules, makes everything downstream consume the hardened id.
- detect/player_id.py identity-card fusion — pure reuse of existing functions (~2-3 days), no GPU/labeling, produces the stable id the whole product hangs on.
- Team REFUSE / one-sided-vest hardening (~1 day) — turns a confidently-wrong 7-7 into an honest 'unassigned', directly de-risking every team-conditioned output.
- Web canvas 2D replay player — mostly plumbing off continuous_state, a few-hundred-KB payload, renders client-side at 60fps, iframe-embeddable; the visible 'wow' for B2B, zero server compute.
- Position-derived analytics core (tempo/territory/hull/Voronoi) — CPU numpy/scipy, no labeling for the metrics themselves, self-normalizing percentiles so it works on the current relative_m calib.

## En büyük riskler
- Appearance ReID is at chance at night (measured intra 0.59 ~ inter 0.58): any individual-appearance identity signal is noise and would silently swap players. Mitigation: identity = motion continuity only (cannot-link DSU + metric gates); appearance restricted to a confidence-gated 2-class team cue, enforced as a hard code invariant.
- Team split is documented-unreliable (yellow vest ~ grass hue, mixed-kit team, Fenerbahce jersey blending): it can ship a confident wrong 7-7. Mitigation: REFUSE path (team_id=-1) + one-sided-vest mode; success on the mixed-kit clip is a CORRECT refusal, not a forced split.
- The ball is genuinely invisible for long night stretches and airborne ball has no recoverable height on one monocular camera. Mitigation: status=unknown is first-class, coverage % always reported, airborne flagged metric_status='airborne_unreliable', the player-position proxy stays rejected, fabrication audit must be ~0.
- 60-min scaling: the single-shot N x N stitch and dense scrums blow up memory/time. Mitigation: overlapping windows sized by tracklet count with Level-2 cross-window stitch only in the overlap zone.
- venue_autocalib must be truly camera-agnostic across different aspect/focal/distortion/resolution or generalization and pooling fail; a bad calib yields plausible-but-wrong metric output. Mitigation: fail-closed QA gate rejects the run; keep gates in relative_m until an on-site anchor exists.
- Scale stays +-13% (height/focal ambiguity) and single-venue (cankaya) threshold tuning may not generalize. Mitigation: relative_m / percentiles by default, m/km-h/sprint only in verified exact mode, thresholds self-normalized to the clip and flagged provisional until multi-venue pooling.
- Far-third recall gap (~33% of rows, ~60px players) leaves partial/substitute ids sparse and biases collective shape. Mitigation: continuous_state fills shape/occupancy (conf<1, excluded from load), windows below an observed_frac floor are greyed, counts never forced to 14.

### In-game evaluation / analytics — position-derived, team-optional match insights ("oyun içi değerlendirme")
